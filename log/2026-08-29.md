# 2026-08-29 修改日志

## 一、混沌胃袋"弃1抽1"改为玩家选择弃牌

- 之前混沌胃袋（形态 38）回合开始的"弃1抽1"复用了炸矛的
  `resolve_pending_discards(count=1)`，是**随机弃**，与卡面语义不符
  （应为玩家选择弃 1 张）。
- 现改为**玩家选择弃**：回合开始（`on_turn_start`）只判断手牌是否
  存在可弃卡（`can_discard` 过滤生物卡/插入卡 49/50 等），有则设置
  `statuses.forced_discards = 1`，回合**暂停在 TURN_START**，播报
  "混沌胃袋：获得动能，需选择1张弃置（弃后抽1）"；无可弃卡时跳过弃/抽，
  播报"无牌可弃，获得动能"。动能（按上回合剩余能量 ×2）仍在回合开始即时获得。
- 弹道炸矛保持**随机弃**不变（`resolve_pending_discards` / `pending_discards`
  字段不变），二者字段分离、互不污染。

### 回合暂停与恢复机制
- 新增 `CombatStatuses.forced_discards` 字段：表示玩家须手动选择弃置的
  张数，**不自动结算**（区别于 `pending_discards` 由系统随机结算）。
- `begin_turn`：`enter_phase(TURN_START)` 后若 `forced_discards > 0`，
  不再进入 DRAW/PLAY，直接返回，等玩家通过 `discard_card` 完成弃牌。
- 新增 `_resume_chaotic_stomach`：玩家弃满 1 张后由
  `_discard_indexes` 触发——补抽 1 张（抽牌堆空先 `reshuffle`），
  再 `resume_after(TURN_START)` 进入 DRAW/PLAY，与原"弃1抽1+正常抽"
  净效果一致，仅弃牌由玩家选、时机延后到玩家弃牌后。

## 二、手牌超限改为点击结束回合自动进入强制弃牌阶段

- 之前手牌超过上限时点"结束回合"会**报错** `hand_limit`（"仍需弃 N 张"），
  前端再自行切到弃牌模式；体验割裂。
- 现改为：`end_turn` 检测到超限（`effective_hand_size - hand_limit > 0`）
  时**不报错**，而是设 `forced_discards = 超限数`、切到 `弃牌阶段`、
  播报"手牌超上限，需弃 N 张"后返回；玩家弃到上限后再点"结束回合"
  才真正结束（进入 TURN_END 并轮转）。
- `_discard_indexes` 支持 `forced`：`forced > 0` 时允许在任意阶段弃牌
  （不再受"仅出牌/弃牌阶段"限制），弃后递减 `forced_discards`；回合开始
  阶段还额外限制"只能弃刚好 forced 张"避免顺势多弃。普通手动弃牌
  （`forced == 0`）行为完全不变。

## 三、前端红框弃牌自动进入 + 结束回合按钮调整

- `MatchView.you` 新增 `forced_discards` 字段；`rooms._snapshot` 下发
  当前玩家自身的 `forced_discards`。
- 新增 `forcedDiscard = 我方回合 && forced_discards > 0`；`discardMode`
  改为 `手动切换 || forcedDiscard`，即后端要求强制弃牌时**自动进入红框
  弃牌**，与手动"进入弃牌"按钮表现一致（红框、卡牌点击即弃），无需玩家
  手动切换；强制结束后红框自动退出。
- 点击弃牌的 `setDiscardDraft` 改为只保留**手动**模式（`manualDiscardMode`），
  避免强制弃牌污染手动切换状态、导致强制结束后红框残留。
- "结束回合"按钮：超限时**可点击**（点击即进入强制弃牌阶段，标签
  "还需弃 N 张"）；处于强制弃牌中时禁用（标签"弃牌中…"），必须先弃完。
- "进入弃牌"按钮在强制弃牌期间禁用但仍显示 active（变色），符合
  "原本的进入弃牌按钮照常变色"的要求。

## 六、多人房间扩展（座位 / 阵营 / 回合顺序 / 胜利条件）

- 单人对局扩展为多人房间：容量上限 **8 座位**，房主可动态增删座位、
  打乱座次、强制移动玩家到指定座位。
- 玩家元数据扩展为 `seat_id`、`user_id`、`display_name`、`team_id`、
  `is_alive`；座位卡片按 `seat_id` 排列，阵亡玩家仍占座但回合跳过。
- 回合顺序按 `seat_id` 序号轮转，跳过已阵亡玩家。
- 胜利条件改为**敌方阵营全员阵亡**（不再是单挑的 HP 归零）；
  3+ 人对局跳过首回合锁血机制。
- 阵营色边框（6 色）区分敌我；房主权限绑定 `client_id`，不再因换座丢失
  （之前直接交换 player_id 会导致房主权丢失）。
- 打乱座次时整槽保留玩家数据（之前只交换 id 会丢配置）。

- **名称被遮挡**：座位卡片名称加 `padding-right: 44px`，避免徽章压字。

  保留座位 / 角色 / 阵营 / 名字，仅重置准备状态。
